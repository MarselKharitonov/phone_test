# Домашний сервер: заготовка

`python -m server.app` — экспериментальный HTTP API, только loopback `127.0.0.1:8765`. Требует Pillow и переменную `STYLIST_SERVER_TOKEN` длиной не менее 32 символов. Токен не печатать и не добавлять в Git. Задачи хранятся в памяти, с удалением через час; изображения после обработки сразу очищаются, так как генерация не подключена. При перезапуске все задачи теряются. Не открывать сервер в интернет и не использовать фото реальных пользователей.

Передача с iPhone требует отдельно настроенного доверенного HTTPS reverse proxy и авторизации в закрытой сети; это ещё не реализовано. Сервер не проверяет владельцев отдельных задач, один токен даёт полный доступ. Это не production.

`KaggleAdapter` намеренно отклоняет отправку: не проверены приватность, изоляция задач, удаление данных и применимость условий. `FakeAdapter` возвращает ошибку, не изображение. Для полноценного сервера ещё нужны проверка изображения декодированием, нормализация EXIF, контроль размеров выходного кадра, TLS, аутентификация, журналирование без секретов и надёжная очередь. Все эти меры описаны в `docs/server-contract.md`.

`stylist/sizing.py` сопоставляет только введённые мерки тела с таблицами тела конкретных вариантов; неподтверждённые размеры изделия не конвертируются в размеры тела. Подключён к API каталога, но ещё не подключён к интерфейсу iPhone.

Пример формата импорта — `server/catalog.example.json` (выдуманный товар, не для показа как реальный). На домашнем сервере после заполнения своего JSON:

```powershell
python -m stylist.catalog_import .\catalog.json --db .\catalog.sqlite3
```

Импорт транзакционный. Значения `updated_at` и `observed_at` — время фактической проверки, размеры из источника в сантиметрах, тип `body` или `garment`; источник сетки обязателен. `POST /v1/size-recommendations` принимает `product_id`, `measurements` и список `required`; рекомендации не являются гарантией посадки.
