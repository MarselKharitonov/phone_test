# Контракт будущего домашнего сервера

Статус: проектирование; сервер и мобильный сетевой клиент ещё не реализованы.

- `POST /v1/tryons`: аутентифицированная multipart-загрузка фото человека и вещи, категория и тип кадра, согласие и идемпотентный ключ; ответ — идентификатор задачи.
- `GET /v1/tryons/{id}`: доступен только владельцу задачи; статусы queued / running / succeeded / failed, без фото в логах.
- `GET /v1/tryons/{id}/result`: изображение только после проверки авторизации.
- `DELETE /v1/tryons/{id}`: удаление локальных изображений и постановка на удаление удалённых копий, с отражением ошибок удаления.

Безопасность до реализации: защищённый канал и авторизация, ограничение размера и распознавание формата, ограничение запросов, хранение секретов Kaggle на сервере, очистка метаданных, согласие на передачу Kaggle, проверка приватности notebook/dataset/output и отсутствие утечки через версии и логи. Нельзя открывать домашний сервер в публичную сеть без защиты. Простой IP-адрес не обеспечивает HTTPS; способ доверенного TLS для домашней сети ещё не выбран.

Kaggle — пакетная среда, не гарантированный online API. Python SDK проверен только запросом на чтение списка notebook. Передача файла, запуск и получение результата не тестировались.
