# Ручной эксперимент на Kaggle

Это не production API и не гарантированно бесплатный сервис. Не запускалось и не проверялось в Kaggle. До запуска проверить применимые условия, квоту GPU, приватность notebook/dataset/output и лицензии каждой модели и зависимости. Не загружать клиентские фото. Использовать только собственные тестовые данные и явное согласие людей; даже private-объект передаёт данные сторонней платформе.

1. После проверки условий самостоятельно создать private notebook, включить GPU и при необходимости сеть; убедиться, что данные и результаты не будут опубликованы.
2. Предоставить notebook копию проекта и приватные тестовые файлы `person.png` и `garment.png` способом, соответствующим настройкам Kaggle. Не помещать ключи или персональные фото в публичный notebook.
3. В отдельной среде notebook установить [официальный FASHN VTON v1.5](https://github.com/fashn-AI/fashn-vton-1.5) и получить его веса по инструкциям автора после проверки лицензий и сетевых условий. Никакие команды не выполняются автоматически из этого проекта; пути зависят от конкретного notebook.
4. Из корня копии проекта выполнить, подставив свои пути:

```bash
python run_fashn.py --person /path/person.png --garment /path/garment.png \
  --weights /path/weights --output /path/result.png --category tops --frame waist
```

`--frame` задаёт оператор, это не детектор тела. Частичный кадр допускает только `tops`, но модель может изменить фон, лицо и другие части кадра; встроенной маски или проверки SKU нет. Выход, у которого размеры не совпадают с исходным после EXIF orientation, отклоняется, а не обрезается. Некоторые модели возвращают изображение в фиксированном разрешении — в этом случае требуется отдельно разработать и испытать безопасную геометрическую реконструкцию; код не выдаст изображение.

Результат — только для ручной оценки, не для клиента. Записать время, версию модели, тип GPU, категорию, исходный размер, изменения лица/фона/позы и SKU, а также неудачные запуски. По окончании удалить тестовые копии и выходы в notebook/dataset согласно действующей политике платформы; полное удаление резервных копий не обещается.
