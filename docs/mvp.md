# Технический план

## Этап 0: тестирование без нагрузки на рабочий компьютер

1. Подготовить собственные фотографии человека и предметов одежды с подтверждёнными правами. Не выдумывать цены и ссылки. Использовать только материалы с явным согласием на выбранную обработку и передачу.
2. Проверить доступность аккаунта и условия Kaggle, квоты, приватность, доступ в сеть и возможность запуска. Кандидат модели — [FASHN v1.5](https://github.com/fashn-AI/fashn-vton-1.5), после проверки лицензий всех весов и зависимостей. Рабочий компьютер не используется для GPU, загрузки моделей и тяжёлых зависимостей.
3. GPT Image через API — отдельный адаптер редактирования по фото человека и SKU. Для РФ доступ заблокирован региональными условиями OpenAI; не обходить ограничения. Проверить доступность для реальной юрисдикции и использования до подключения.
4. Тесты Kaggle не приравнивать к коммерческому хостингу или гарантированно бесплатному продакшену. Затем перенести модель в совместимый worker на платном GPU, только после согласия владельца на бюджет. Mock не является примеркой.

## Этап 1: безопасная архитектура

Мобильный web (English-first, i18n) → API FastAPI → PostgreSQL + приватное временное хранилище → очередь → worker/VTON и QC. Локально SQLite и файловое хранилище только для разработки; реальная архитектура — PostgreSQL и надёжная очередь с lease/retry/dead-letter. Бесплатность любого хостинга и применимость для РФ не подтверждены.

Интерфейсы: `MarketplaceProvider` (суточный импорт), `VtonProvider` (одна операция + стоимость/версия), `PaymentProvider` (checkout, подтверждение webhook, refund); интерфейсы по умолчанию выключены. Изолировать ML от edge runtime.

Предлагаемые API: `POST /consents`, `POST /uploads`, `POST /outfits/preview`, `POST /checkout`, `POST /webhooks/{provider}`, `POST /tryons`, `GET /tryons/{id}`, `DELETE /uploads/{id}`. Каждый запрос владельца аутентифицируется и авторизуется; никакие права не доверяются frontend.

Таблицы: `users`, `consents` (версия/цель/отзыв), `uploads` (объект, expiry), `products` (страна, валюта, цена и время, товарная ссылка), `variants` (размер, остаток), `size_charts` (источник/тип мерок/версия), `asset_rights` (источник, документ, разрешённые цели, территория, expiry), `jobs` (статус, попытки, trace, version), `payments`, `webhook_events` (уникальность provider/event), `credit_ledger` (неизменяемые проводки, уникальный ключ операции).

Импортировать только записи, где права явно подтверждены для VTON; неопределённое значение — запрет. Данные об остатках и ценах показывать со временем последнего обновления, не выдавать вчерашнюю доступность за текущую. Суммировать только одну валюту и рынок.

Подтверждённый подписанный webhook сверяет order, продавца, сумму и валюту; в одной транзакции дедуплицирует событие и начисляет кредит. Идемпотентный `POST /tryons` атомарно резервирует кредит и создаёт задачу; неуспех освобождает резерв, результат списывает, возвраты и chargeback создают компенсирующие записи. Исключить повторную генерацию из-за повторов webhook/worker. Проверять актуальное состояние через PSP при необходимости.

## Видимые зоны и размеры

Границы определяются по ориентации фото, точкам тела и уверенности; при неопределённости — запросить другое фото, а не генерировать недостающую часть. Плечи/частичный торс: только видимая верхняя зона; по пояс: верх, без брюк и обуви; полный рост — только реально видимые зоны. Для модели без управления маской: ограничить изменения проверенной маской при композитинге с оригиналом и проверять размер/геометрию на выходе; если зона или результат сомнительны, отклонить. Это не доказывает сохранение деталей одежды или реалистичность швов.

Размеры: сопоставлять введённые сантиметры с конкретной сеткой для SKU и категории. Различать мерки тела и изделия; припуски для посадки применять только при наличии подтверждённых данных соответствующей сетки. Рассмотреть все обязательные измерения, наличие конкретного размера, диапазоны и границы. Если данных/размеров нет, конфликтуют или непонятен тип сетки — `insufficient_data`, без угадывания по весу. Объяснение, confidence как некалиброванный качественный уровень, не гарантия посадки.

## Фото и приватность

Принять только изображения ограниченного размера и типа, проверить содержимое декодированием, исправить EXIF orientation и удалить EXIF; приватное хранение с шифрованием и короткоживущими ссылками, доступ только владельцу. TTL например 24 часа — проектное предложение, не юридическая норма; удалять оригинал, результат, копии, очередь и по возможности у подрядчика; отдельно согласовать backup и сроки удаления. Не писать фото, мерки, токены и ссылки в логи. Получать осознанное согласие на цели и внешнюю обработку, описать отказ, отзыв и пользовательское удаление; проверить требования выбранного рынка до работы с реальными людьми.

## План сравнительных испытаний

Кандидаты: GPT Image API при законной доступности и согласованном бюджете; FASHN v1.5 на Kaggle при подтверждённых условиях; тот же FASHN v1.5 на платном GPU после разрешения. Пока это **не результаты сравнения**. GPT Image — генеративное редактирование, а не гарантированное сохранение SKU; тестировать отдельно от специализированной VTON-модели.

Зафиксировать 30+ согласованных пар person/SKU: портрет, по пояс, полный рост; разные позы, освещение, цвета кожи и типы тела; принты, карманы, текстуры, слои. Использовать одни и те же входы и категории; две независимые оценки и журнал ошибок. Особо проверять отсутствие добавленных частей, рамку, лицо/фон/позу, SKU и руки. Предварительно утвердить критерий успеха; измерять p50/p95 end-to-end, число попыток, условно успешные и непригодные результаты, счета и idle. Цена успешного результата = все расходы испытания / число годных результатов, включая технически успешные, но визуально проваленные, повторы и idle. 30 — плановый минимум для пилота, не основание для точной статистики. Не запускать платные тесты без разрешения.
